Turn a feature branch into an explainer someone can trust.

Point an agent at your current branch. It analyses what changed and writes a spec; build.js turns that into one self-contained HTML page — a real call graph, the actual source at the actual line numbers, and line-by-line explanations of intent, not syntax. Built for the moment someone says “read through this branch and tell me how it works.”

01

Analyse

The agent reads the branch — changed files, uncommitted work, callers and callees — and writes a spec: { "from": 48, "to": 54 }, never pasted code.

02

Build

npx feature-explorer build reads those exact lines off disk and validates the structure — dangling edges and overlapping boxes are rejected.

03

Verify

npx feature-explorer verify diffs every displayed line against the working tree and exits non-zero on any mismatch.

The part that makes it trustworthy

A confidently wrong diagram is worse than no diagram.

Anyone can ask an LLM to draw an architecture diagram. The problem is you can't tell whether what it drew is real. Two mechanisms deal with that — one at write time, one that checks the result anyway.

Snippets are correct by construction

You never paste code into the spec. You give a file and a line range; build.js reads those lines off disk. Text and line numbers cannot drift, because nobody retyped them.

spec.json
{ "from": 48, "to": 54, "n": "The fix. Defaults first, caller options over them, then methods is recomputed last…" }

And then it's checked anyway

verify.js re-parses the built page and diffs every displayed line against the working tree. Run it before you share a page, and again after anyone hand-edits one.

terminal
$ node verify.js demo/demo.html demo/ky-retry-methods.spec.json
data block parses: OK
structure: 14 nodes, 16 edges — OK

code lines checked: 138   mismatches: 0
✓ VERIFIED — every displayed line matches the working tree

What you get in the page

Not a dependency dump. A story with evidence.

The graph provides orientation, the source viewer provides evidence, and the line-by-line explanation provides understanding — together, not as three separate tools.

Architecture graph

Meaningful nodes — functions, routes, services, stores, types, tests — grouped into real subsystems, with labelled directional edges. Anything inferred rather than read from a literal call is marked ⟨inf⟩.

Feature Flow

The primary execution path, numbered and highlighted, while everything else fades — so the graph shows what actually matters first.

A real node inspector

Change status, why the file is part of the feature, clickable relationships — called by, calls, reads, store operations — and breadcrumb navigation back through them.

Line-by-line, by intent

“Prevents the request from being retried when the backend marks the failure as non-recoverable” — not “this is an if statement.”

Honest gaps

Non-contiguous excerpts stay honest — gaps are marked ⋮ and line numbers are never renumbered or stitched together to look tidier.

Search, filter, navigate

Changed-files panel grouped by subsystem, status and subsystem filters, collapsible groups, pan/zoom, client-side search. Dark, keyboard-friendly, no network calls.

Install

One line. No clone.

Published on npm — npx fetches it fresh each time, nothing to install, nothing left behind in your project.

→

In your own repository, on the branch you want explained, tell your agent — Claude Code, Cursor, Copilot, Aider, or plain chat with file access:

say this 
Run npx feature-explorer init and follow what it prints, on the current branch.

It reads the branch, writes a spec, then npx … build and npx … verify render and check the page the same way — into .feature-explorer/ at your repo root, untracked. You get back one HTML file — open it. No server, nothing to deploy, nothing stays installed.

Using Claude Code? For the /feature-explorer slash command instead of typing the sentence every time, clone it once and symlink it in: git clone https://github.com/nikhilyadavvvv/feature-explorer.git && ln -s "$PWD/feature-explorer" ~/.claude/skills/feature-explorer
